# AGENTS.md — Riskfate: The Living Guild

## 1. Репозиторій та межі

- Офіційний репозиторій: https://github.com/levian47/riskfate-the-living-guild
- Основна гілка — **main**. Це окрема гра, а не частина Riskfate 3D Pro.
- Перед роботою перевірити актуальний main, відкриті PR і наявні файли, прочитати README.md, GAME_CONCEPT.md, PLANNING_FOUNDATION.md та ROADMAP.md.
- Джерело ідей: https://github.com/levian47/riskfate-3d-pro. Його документи можна **читати** та аналізувати; не змінювати той репозиторій і не переносити його правила, код чи ресурси автоматично.

## 2. Повноваження та збереження рішень

- Аналіз, підготовка ТЗ, рекомендації та аудит **не дають** дозволу самостійно змінювати код, затверджені механіки, дизайн, налаштування чи main.
- Кожну зміну виконувати в межах конкретного доручення власника.
- У документах чітко розрізняти: **погоджено для The Living Guild**, **пропозиція**, **кандидат із 3D Pro**, **реалізовано і перевірено** та **відкрито**.
- Не підміняти рішення власника вигаданими порогами, формулами, цифрами балансу чи готовністю функцій.
- Погоджені механіки й ресурси не переробляти без прямого дозволу; суперечності явно повідомляти.

## 3. Основні продуктово-технічні обмеження

- Основна цінність гри — **автономні герої, якими опосередковано управляє гільдія**, та пов'язана з їхніми діями економіка.
- Візуальний напрямок — простий масштабований векторний UI та легке 2D-відображення подорожей/боїв; не ускладнювати без потреби піксельною графікою, інтер'єрами, складними анімаціями чи 3D.
- Не припускати, що новій грі потрібен MMORPG-сервер, мережевий акаунт, фізика повного 3D-світу або штучний інтелект на нейромережах.
- **Рушій ще не обраний.** Не створювати Godot-проєкт, Web-клієнт, CI або конфігурації експорту до рішення власника.
- Перевага простим стандартним інструментам, станам і правилам поведінки, відокремленню симуляції від відображення. Не вводити архітектурні абстракції про запас.

## 4. Git та якість роботи

- Для суттєвих змін створювати робочу гілку й PR; **не зливати PR в main і не видаляти гілку без прямого дозволу власника**.
- Один відповідальний виконавець на завдання; перед редагуванням перевірити, чи немає паралельних конфліктних робіт.
- Після змін перевірити diff, посилання, відсутність випадково змінених файлів; для коду — відповідні тести й доступний спосіб ручної перевірки.
- Не прирівнювати «код написано», «тести пройшли», «власник прийняв» і «в main інтегровано».
- У звіті вказувати змінені файли, SHA комітів/посилання на PR, результати та обмеження перевірок.
- Тримати ТЗ короткими й змістовними; не створювати дублікатів, архівів і непотрібних каталогів.

## 5. Призначення документів

- GAME_CONCEPT.md — механіки, економіка, автономність, пропозиції й відкриті питання.
- PLANNING_FOUNDATION.md — технічна основа та її статус.
- ROADMAP.md — послідовність робіт і підтверджений прогрес.
- README.md — призначення, чинний фактичний стан та запуск (коли він з'явиться).
- AGENTS.md — інструкції для виконавців.

Будь-яку ідею з Riskfate 3D Pro адаптувати окремо до ігрової ролі автономного героя та управління гільдією.
